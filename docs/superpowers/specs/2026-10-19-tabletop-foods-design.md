# 立体食物摆盘 / Tabletop Foods

状态：用户已确认“按这个方案开始制作”。此文档描述要制作的成品。

## 用户的目标

用户希望所有食物都有立体外观，并能右键放在地上。用户已明确选择“每种食物都有自己的立体形状”，而非将原来的平面图标简单加厚。

用户进一步确认首版范围为“先做全部原版食物和冒险零食包”。

沿用本次会话已确认的 Minecraft Java 26.2、Fabric Loader 0.19.3、Java 25，以及用户现有的 PCL2 实例。成品是独立模组，不修改冒险零食包或随机人形村民的源码。

## 预期外观

- 为所有原版可食用物品制作与食物种类对应的方块风格立体模型，包括苹果、面包、胡萝卜、肉类、鱼类、浆果、曲奇、汤碗和蜂蜜瓶等。
- 加速苹果、夜视胡萝卜、跳跃软糖沿用其各自主题，获得对应的立体形状。
- 手持、掉落、物品栏和摆放状态均使用相同的立体食物外形，按展示场景调整朝向和大小。
- 蛋糕已有完整立体方块与摆放、食用机制，保留其原版行为。
- 模型由长方体构成，不生成写实贴图；优先引用游戏与零食包现有纹理，避免依赖在线素材。

开发者决定：首版保证所有原版可食用物品及冒险零食包三种食物的定制形状。其他模组通过食物组件识别、允许摆放，展示其原有模型；新增食物的专用造型可后续添加。README 应明确这个兼容范围，不能声称未知模组的每种食物也都有定制模型。

## 玩家操作

1. 手持食物，对准有支撑的方块顶面右键，摆放一份食物。食物固定在表面，不旋转、不上下漂浮，也不会像掉落物那样到时间消失。
2. 每个摆放位置放一份，食物随玩家朝向摆正；已有食物时阻止重叠摆放。
3. 对准空气长按右键，继续按原版方式吃食物。食物的饥饿恢复、药水效果、容器返还等逻辑保持原有行为。
4. 空手右键已摆放的食物，将其收回背包；背包满时掉落到玩家身边。击打也能收回一份食物。
5. 生存模式成功摆放才扣除一个物品；创造模式不扣物品。食物的名字、自定义组件和效果数据需要完整保存。
6. 破坏支撑方块后，食物作为普通掉落物掉下；避免空中悬浮。
7. 普通右键优先保留箱子、工作台等常用交互；需要在这些方块上摆食物时使用潜行右键。具体覆盖的交互方块由实现阶段核实。

开发者决定：摆放发生在顶面，按方块中心对齐，支持完整方块及半砖等有实体顶面的支撑。食物不阻挡玩家行走。首版不添加餐盘、切片、腐烂或从地上直接吃食物等额外机制。

## 保存与联机

- 摆放的食物是有持久化物品数据的独立实体，服务器是摆放、扣除、捡回与掉落的权威。
- 保存后退出并重进世界，食物仍位于原处，物品数据保持一致。
- 单机自动使用内置服务器；联机时服务器和各客户端均需安装此模组。
- 仅支持玩家有交互及放置权限的地方，旁观模式不能摆放或捡取。

## 实现方向（由开发者决定）

使用 Fabric Java 模组和原版模型 JSON。注册一种摆放食物实体，保存完整的单个 ItemStack，并同步给客户端；渲染器以固定位置和旋转绘制食物的物品模型。客户端资源替换已支持食物的物品模型，未知模组食物沿用自身模型。

实现细节如事件注入点、26.2 的保存与渲染 API、模型几何尺寸、支持检查频率、文件组织和构建脚本，由开发者在现有缓存和官方 API 文档中核实后选择。识别逻辑应基于食物组件，已具有原版方块摆放行为的特殊食物按上述例外处理。

已核实 Fabric API 提供 `ItemEvents.USE_ON`，位于 `ItemStack.useOn` 调用物品自身 `useOn` 的阶段，可在原版方块交互后处理摆放。设计审阅已完成，无必须补充的重要问题。

实现阶段补充：只将同时带有食物与消耗组件的物品视为玩家食物，排除鱼桶；该事件返回 `null` 才会继续原版处理。潜行右键可种植的表面时保留原版种植行为。
